# 上游中心

管理员通过侧栏「上游中心」进入，地址为 `/admin/upstreams`。

页面包含「上游管理」「监控中心」「智商监控」「OAuth 监控」「站内监控」五个 Tab。上游管理采用全宽横版卡片：左侧展示厂家、钱包与今日经营概况，右侧逐行展示 Key 分组、自动获取的倍率、监控记录条和该 Key 的消费数据。顶部使用紧凑统计与筛选栏。

## 手动排序

四个 Tab 的筛选栏均提供「手动排序」入口；每家上游卡片内另有「分组排序」，用于调整该上游的 Key 分组。至少有两项时可操作。弹窗中可拖动左侧手柄，也可点击右侧上移、下移按钮；点击「保存排序」后生效，取消则不保存。

排序按上游、独立监控、单家上游的 Key 分组、智商监控计划、OAuth 监控计划分别保存到服务端，所有管理员共享，刷新页面或重启服务后仍保留。即使页面正在搜索或筛选，排序弹窗也显示所属范围的完整列表。新增条目排在已手动排序条目之后；Key 分组更换上游或转为独立监控、计划在智商与 OAuth 类型之间切换时，清除旧范围的位置并加入新范围末尾。尚未手动排序的列表沿用原来的默认顺序。

排序仅改变列表展示，不改变启用状态、检测间隔、正在执行的任务、账目和历史作品时间顺序。若保存时列表已被另一处新增、删除或移出，界面会提示重新加载完整列表再排序，避免遗漏条目。

## 上游管理

可以先添加厂家，再为厂家添加 Key 分组；也可以在「添加上游」弹窗中直接批量选择账号管理里已有的 API Key 账号。当前导入列表支持 OpenAI、Anthropic、Gemini 账号，每个所选账号生成一个 Key 分组，服务端读取其地址与密钥，不要求把原 Key 重新复制到浏览器。

导入前可以分别修改分组名称、检测模型和间隔。新增及批量导入分组默认预填 `gpt-5.6-sol`，每 30 秒检测；这是可修改的初始配置，不代表上游或所选协议一定支持该模型。每个分组最多 8 个模型，使用逗号分隔。批量导入的可用性监控默认开启，也可在提交前关闭。已有分组的模型及检测间隔保持原值。

批量导入若部分失败，会保留已创建的厂家和成功分组，并显示各失败项的原因。在当前页面重试只继续未成功项；创建响应丢失时先核对已存在的厂家及账号绑定，出现多个同名同网址厂家时要求明确选择。未完成的导入草稿只保留在当前页面会话内，刷新或离开页面前应先处理失败项；之后可从已创建厂家的「添加 Key 分组」继续。

已有分组的账号导入区域直接显示在编辑弹窗中。一个分组可以绑定多个已有账号，但这些账号必须使用同一地址与密钥，每个账号只能有一个活动绑定。编辑时 Key 留空表示保留原密钥；换绑使用不同 Key 的账号时需要重新填写对应 Key。重复的活动厂家 Key 分组会被后端拒绝。

「上游 Key 分组」与本站售卖分组分别管理。经营数据按实际承接请求的绑定账号归集，不把整个售卖分组的消费都算给一家上游。绑定从保存后生效，不自动追溯无法核实的历史 Key。

每个 Key 分组下面展示最近 60 次检测记录，左旧右新。记录条沿用原样式，高 22px，各条宽度随所在区域自适应铺满，不设固定总宽度：

- 绿色：成功且耗时低于波动阈值。
- 黄色：请求成功，但耗时达到波动阈值。
- 红色：请求失败、超时或响应内容校验失败。
- 灰色：尚无记录。

卡片突出显示固定「7 天成功率」与「最新延迟」；切换模型时，两项数字和记录条同步切换。7 天成功率包含正常和波动的成功检测，颜色沿用渠道监控的红黄绿连续映射，不受页面所选 24 小时或 30 天统计窗口影响。最新延迟取最近一次检测，包括失败检测；最近记录未提供延迟时显示 `—`，不回退到较早记录或平均值。延迟低于配置的波动阈值为绿色、达到波动阈值为黄色、达到配置超时时间为红色。

记录条显示的是最近 60 次采样，不代表完整统计窗口。悬停任意已检测细条可查看时间、模型、HTTP 状态、延迟及检测错误，并复制详情；错误仅包含服务端允许保存的诊断信息。「上次更新 N 秒前」每秒刷新，表示所选模型距离最近检测的时间，不代表每秒向上游发起请求。无记录时显示等待首次检测。详情中的 24 小时、7 天、30 天可用率仍按各自窗口计算，平均和 P95 延迟只统计成功样本；延迟为完整非流式模型响应耗时，单位毫秒。

## 独立监控

监控中心可直接添加名称、HTTPS API 地址、Key、模型和间隔，不需要创建厂家或绑定业务账号。协议支持 OpenAI Chat Completions、OpenAI Responses、Anthropic 和 Gemini。

也可选择现有 API Key 账号导入独立监控。保存时由服务端一次性复制该账号的协议、地址和密钥，并为监控独立加密保存；浏览器不接收原始 Key，且不会建立业务账号绑定或修改账号采购倍率。源账号需要可用、未禁用，且符合过期策略。导入后修改源账号不会自动改动此监控；需要换 Key 时可再次导入或手动填写。编辑已有监控并重新导入只替换来源凭据，模型和检测间隔仍保留当前设置。

来源账号的地址与协议必须配套使用。取消所选来源后，如果当前地址或协议已不同于已保存监控，必须重新选择来源或填写 Key，不能把原监控的隐藏密钥沿用到新地址。换凭据后，余额与倍率等待新身份同步，不显示旧凭据的历史快照；原检测记录仍保留。

新增独立监控默认使用 `gpt-5.6-sol`，每 30 秒检测，间隔允许 30–3600 秒；默认超时 45 秒、波动阈值 6000 毫秒。已有监控的模型与间隔保持原值。保存启用的目标后安排首次检测。任务在服务端执行，关闭浏览器不影响。调度独立于原渠道监控 V1/V2 模式；多实例使用数据库租约防止重复执行。

管理员可暂停定时任务，或对暂停目标执行一次手动检测。模型列表获取失败时仍可手动填写完整模型 ID。

多模型分别展示统计，监控中心保留小卡布局：顶部第一行展示站点与状态，第二行在网址旁紧邻「访问网站」入口。模型信息采用较弱的小字样式，与倍率保持同一行，多模型仍可切换。成功率与最新延迟使用对齐的两列紧凑指标，下方保留记录条、下次检测时间和操作区。使用相同的 60 条自适应记录、三色状态、固定 7 天成功率和每秒更新的时间标签。未检测、暂停和数据过期都有独立状态；一个模型成功不会抹去其他模型的异常。这里的定时可用性监控与下文的智商监控是两套独立任务。

独立监控卡在模型旁显示该 Key 自动同步的有效倍率，未获取时显示 `—`，过期或同步错误时保留已知值并以黄色标记。域名旁的「访问网站」按钮在新标签页打开 HTTP/HTTPS 源站，只保留协议、主机和非默认端口，不携带 API 路径、用户名、密码、查询参数或片段；无有效网站地址时不显示访问按钮。

## 自动获取上游倍率

Key 行及独立监控卡上的「倍率」是从该 Key 对应的上游读取的有效 Token 计费倍率，不是人工填写的标签，也不根据余额变化、请求金额比值或厂家名称推算。

系统首先识别上游 `/v1/usage` 中符合已声明格式的 `billing` 信息；缺失时查询 `/v1/sub2api/billing`。当前有效倍率包含上游返回的用户专属覆盖和峰时因素。详情可查看分组倍率、用户专属倍率、Key 基础倍率及同步时间。`0×` 是有效值；未获取的数据显示 `—`，不默认按 `1×` 展示。

厂家及其 Key 分组、独立监控只要尚未归档，就由后台周期性同步余额与倍率，正常到期间隔约 1 分钟；暂停可用性监控不会停止这项同步。倍率同步不跟随每次可用性检测重复发起。点击「同步余额」会同时尝试同步余额和倍率。页面刷新读取已保存的快照，不直接等待所有上游响应。上游版本不支持倍率接口或响应格式不匹配时显示未提供倍率。失败时保留同一凭据的最近成功倍率并标记过期或错误；较旧的成功快照也会标记过期，不能当作当前报价。

该倍率是上游的 Token 计费信息，不等同于本站售卖倍率，也不会自动改写账号采购配置或重算旧账。模型单价、折扣、套餐和固定次数计费等仍需按实际采购规则核对。

## 余额和账目

余额同步适配提供 `/v1/usage` 的 Sub2API 上游。钱包余额、Key 配额、订阅剩余额度分别显示；不支持该接口的站点仍可进行模型监控。同步失败保留最后成功数据，并显示同步状态和时间。

同一家上游中，相同「钱包标识」表示明确配置为同一共享钱包；同标识且同币种的钱包余额只展示一次，选用一条完整的真实余额观测，不把多个 Key 的余额相加。不同币种分别显示；Key 配额与订阅额度按 Key 独立保留，不并入共享钱包。属于不同上游用户账户的 Key 应设置不同钱包标识，不会仅凭余额数值相同判断账户关系。

已有可信钱包余额时，同标识下另一 Key 的 401、待同步或不支持响应不会额外生成重复钱包；各 Key 自身仍显示其同步失败状态。没有任何可信余额时保留未知占位，不伪造零余额。

每个 Key 详情显示该 Key 的「上游今日消费」「上游累计消费」，在检测记录和收支 Tab 都可查看；横版卡片的 Key 行也显示上游今日消费。数据采用上游的统计口径和日期边界，可能包含站外使用。厂家共享钱包不把多个 Key 的消费数值混加。未知金额为 `—`，真实零消费显示为零。同步失败时分别显示最后成功数据时间和最近尝试时间。

Key 行右侧财务金额以纯数字显示，币种通过悬停提示与详情保留；不把不同币种的金额视为可直接相加。

用户消费是本站账面扣费或订阅额度消耗，不等于现金收入。业务成本沿用请求记账时的采购统计成本及账号倍率；检测成本使用返回的 token 用量和可解析的采购价格估算。未知检测成本保留为空，不算作免费。

Key 行同时显示今日业务请求数、今日消耗 Tokens 和账号计费。业务请求数只统计归属此 Key 的已记账业务请求；Tokens 是输入、输出、缓存写入与缓存读取之和，以 M（百万）展示，达到十亿时换为 B（十亿）。旧记录的原始使用日志已清理且无法恢复 Token 时，合计显示 `—` 并提示缺失记录数，不将缺失部分当作零；确实没有业务请求时为 `0.00M`。

「账号计费」采用请求记账时保存的账号统计费用及账号倍率，与站内账号统计口径一致：优先取账号统计成本，缺失时取基础总成本，再乘当时的账号倍率。零倍率有效，历史费用不随之后的账号配置变化。它不等于本站用户扣费，也不额外包含监控费；当前等于这批业务请求的已归因业务成本。

预估毛利 = 本站用户消费 − 业务成本 − 检测成本。存在未定价的检测记录时，合计毛利标记为待补全。上游报告的消费与本站归因金额分开保存；站外用量、时区和账单范围不一致时不强行对齐。

经营明细独立于普通使用日志保存，日志清理不会删除已记录的上游账目。修改厂家归属、Key 或账号绑定不会重写旧账归属；账号原接入凭据变化时，其活动绑定关闭，需要核实后重新关联。时间归因采用使用日志的完成记账时间。

删除厂家或目标为归档操作：停止后续监控并结束绑定，保留历史记录与账目。正在检测时需等该轮完成，以免遗漏已产生的请求和成本。

## 智商监控

智商监控用同一道固定生成任务保存作品，供管理员比较不同线路在不同时间的表现，不提供自动智商评分，也不能用单次作品证明实际底层模型身份。

测试参数如下：

- 模型：默认 `gpt-6-astra`，可选 `gpt-6.1-sol`；同一上游分组、OAuth 账号或站内分组可以分别创建两个模型的计划，独立保存配置与记录。
- 思考强度：`high`。
- 提示词：`创建一个 HTML，内容是用 SVG 绘制一个鹈鹕骑自行车的 2D 动画。你不需要任何测试。`

新建计划支持三种来源：

| 来源 | 配置与执行方式 |
| --- | --- |
| 上游 Key | 选择已在上游管理保存的 OpenAI 兼容 Key 分组，复用其服务端凭据。执行时获取并保存该次上游倍率快照。 |
| 本站分组 | 选择活动的 OpenAI 或 composite 分组，服务端为当前管理员创建专用监控 Key，通过本站真实网关路由执行，并遵循正常分组权限与计费。 |
| 外部地址 | 填写公网 HTTPS 地址和 API Key，可补充上游、分组、倍率及其他备注。倍率备注只是备注，不作为已验证的自动倍率；当前外部来源没有自动倍率采集快照。 |

请求接口可选择 Responses 或 Chat Completions，最长等待时长按分钟点选，提供 **5 / 10 / 15 分钟**，新建计划默认 **10 分钟（600 秒）**，智商监控和 OAuth 鹈鹕测试使用同一设置。已排队、正在执行及历史记录保留提交时的超时快照，不会被追溯修改。所选来源必须能接收选定模型与对应协议；仅能获取模型列表不代表测试模型必定可用。

「上游 Key」和「外部地址」使用流式请求接收长时间生成，再汇总为一幅作品；兼容仍返回完整 JSON 的上游。收到完成或失败事件后立即结束本轮接收，不等待对方关闭连接。本站分组和 OAuth 保留原有受限时控制的执行通路。不会在失败后自动重复提交同一次生成，也不会自动更换模型、思考强度或请求接口。

普通可用性监控成功，只说明该次所选模型及接口可用；智商测试的固定模型、high 思考和接口可能与之不同。HTTP 502/503 表示生成请求收到上游或中间网关返回的错误，不等于本站的 15 分钟等待已经到期；对方反向代理和模型路由也可能有自己的限制。新的失败记录会在可获取时展示脱敏后的 JSON 错误说明、错误码和请求编号，便于与上游核查；不保存整段 HTML 错误页或凭证。旧记录无法补回此前未保存的上游详情。

**智商监控的定时开关默认开启，每 5 分钟检测。** 可在保存前关闭定时，之后点击「立即测试」手动执行。间隔提供 **5 / 10 / 15 分钟**及自定义 **30–86400 整数秒**。间隔从本次任务完成后开始计算，同一计划的同类测试不会重叠执行，两类测试可并行。

智商监控、OAuth 监控和站内监控的「手动排序」左侧提供「全部停止／全部开启」，作用于全部未归档计划及已添加的糖果测试，不受当前 Tab、搜索和筛选影响。停止会关闭后续定时并撤下尚未开始的定时队列；正在执行的本次和手动提交的请求继续完成。开启保留原间隔，仍检查来源可用性和 OAuth 周限额。

开启定时且当前没有排队或执行任务时，卡片显示每秒更新的「下次检测」倒计时，格式为 `HH:MM:SS`，以服务端返回的 `next_run_at` 为目标、结合浏览器当前时间计算。正在排队或绘制时显示「本次完成后安排」，任务结束后由服务端按间隔设置新的时间；时间已到、缺失或无效时显示「等待调度」。暂停定时后隐藏倒计时并停止其界面计时器，倒计时本身不会发起检测请求。

执行请求先进入服务端队列，状态依次为排队、绘制中、完成或失败。关闭浏览器不影响已提交任务。每次执行分别保存时间、状态、耗时、HTTP 状态、固定参数、来源与备注快照、可获取的运行时倍率、模型完整文字回复及提取出的 HTML。修改计划不会改写已保留作品；归档计划停止后续调度，存在活动任务时需先等待结束。

默认可同时进行 **8 个鹈鹕测试**，糖果测试有独立的 **4 个并发名额**。同一计划的两类测试可同时执行，糖果不会再等待该计划的鹈鹕绘制完成。两类任务分别领取和补位，入队和任务完成会立即唤醒执行队列；到期扫描与执行独立。同一计划同一测试仍只允许一份活动任务，避免重复请求。配置并发用满时仍会排队，上游和 OAuth 账号自身的并发限制也继续生效。

在 **上游中心右上角 → 并发设置** 中，可调整鹈鹕 **1–256**、糖果 **1–128** 的并发上限，同时查看两类测试当前运行／排队数量。保存后生效，无需重启，刷新或重启后设置仍保留，适用于智商监控、站内监控、OAuth 和上游分组弹窗。调大后空余名额立即用于等待任务；调小后保留正在执行的请求，等占用下降再启动新任务。后台设置优先于部署配置；尚未在后台保存时才使用 `INTELLIGENCE_MONITOR_MAX_CONCURRENCY`、`INTELLIGENCE_MONITOR_CANDY_MAX_CONCURRENCY`，修改这两个部署值需要重启，且多实例应保持一致。

可见的智商监控列表与上游智商弹窗，在任务运行、排队或即将到期时每 **1 秒**统一刷新，空闲时每 **5 秒**刷新；隐藏页面暂停读取。并发设置窗口打开时每 **2 秒**更新运行和排队数量，不覆盖正在编辑的并发值。模型仍需完成自己的生成过程，刷新频率不代表每秒发起一次新测试。

糖果判分遵循 `haowang02/cpa-plugin-codex-candy-eval` 与 `haowang02/codex-candy-eval` 的规则：返回的文字中出现独立数字 `21` 即通过，不再要求特定的“最终答案”句式。支持常见 LaTeX、Markdown 和全角数字；`121`、`210`、`021` 不通过。此规则不是语义结论判断，推导、引文、备选答案中的独立 `21`（以及 `21.5`）也会通过。判分器版本 3 在后台分批重评已保存的旧回复，不重新调用模型，网络错误仍保留失败。

每轮糖果测试只发送 **一次糖果题请求**，使用计划选定模型、思考强度 `high`，不使用工具。答案 `21` 只存在本地评分器中，不发送给模型，也不再附加采样或模型对比请求。各计划继续按后台设置的糖果并发上限运行，并使用该次最长等待时长。

糖果记录条仅按本轮糖果结果着色：请求成功且回答正确显示绿色，回答错误或请求失败显示红色；未执行、排队和执行中保持各自的等待状态。悬浮提示显示答案判定、执行时间、请求模型、思考强度、耗时与错误信息；记录弹窗展示原始回复，便于核对评分。列表仅返回轻量摘要，完整回复在打开详情时加载，继续复用现有面板轮询。每个计划独立保留最近 60 条糖果结果，超过保留数量的记录随原始回复一并物理清理。

智商监控使用横版卡片，展示最近执行状态和作品预览。卡片横向排列最多 20 条已结束执行的作品，左新右旧，可横向滚动；每张作品标记成功或失败，点击可打开对应记录。成功作品的右下角常驻显示总耗时，例如「12 分 34 秒」，缩略图和大图一致；耗时取服务端记录的执行时间，旧记录缺少该字段时用开始和结束时间计算，不包含排队时间，缺失时不虚构数值。“查看作品”仍仅在悬停或聚焦时出现，并避开耗时角标。尚无作品时显示等待或执行中的提示，不填充虚构结果。这个方向与上游可用性监控的 60 条记录相反。

排队或绘制中的任务会在最左侧额外展示鹈鹕骑行线稿，搭配缓慢转动的车轮、沿轮廓移动的描线和轻微跳动的状态点；排队时动画更慢，并标注真实任务状态，不占用 20 条已结束作品的计数。这是本地生成等待动画，不是上游生成结果，也不表示实际完成进度。浅色、深色主题均适配，系统启用减少动态效果时停止动画。作品卡宽度保持 176 像素，预览区域最小高度为 144 像素，并随横版卡片剩余高度伸展，底部记录信息保持独立高度。完成后原位置转为作品预览，页面轮询和预览尺寸变化不会反复重建已展示的 iframe。已完成作品的 CSS/SVG 声明式动画直接在缩略图中播放；“打开”入口在悬停或键盘聚焦时显示，也可点击下方记录信息查看详情。加载已完成结果、失败和没有 HTML 分别显示对应提示。

**每个计划仅保留最近 20 条已结束执行（成功或失败）。** 超出部分连同原始回复与 HTML 从数据库物理删除，不是仅在界面隐藏。排队或执行中的任务不参与删除，因此活动任务存在时总记录数可以暂时超过 20；归档计划也遵循此保留规则。需要长期留存的作品应提前下载。

「历史作品」提供保留记录的分页列表、动画预览、HTML 源码、完整回复和原始 HTML 下载。紧凑预览的逻辑宽度固定为 `960`，逻辑高度按预览区域比例计算且不低于 `600`；详情预览保持固定 `960×600` 逻辑画布。两种预览均等比缩放并居中，避免拉伸或裁切作品；较高的紧凑预览会改变 HTML 的可用视口高度，作品能否填满仍取决于其自身布局。经过清理的内容放在隔离 iframe 内，禁止脚本、外部请求及导航，CSS 与 SVG 声明式动画可以显示。依赖 JavaScript 的作品可能在页面内保持静态，详情预览会提示脚本未执行。源码与下载保留原始生成 HTML；下载后在浏览器中自行打开，原始脚本可能执行，不等同于页面内的受限预览。

### 用户端鹈鹕监测

在「上游中心 → 站内监控 → 用户展示」中，可以开启用户端「鹈鹕监测」，设置页面标题、说明和公告，并勾选需要展示的站内分组计划。功能默认关闭，默认不选中任何计划。此设置只控制展示，不会启用定时任务或发起模型请求；暂停的计划也可以展示已有作品。同一分组的两个模型可以分别勾选，在用户端独立横向展示；检测间隔下方显示「GPT-6 Astra」或「GPT-6.1 Sol」，实际请求模型名不变。

「隐藏生成失败的作品」默认关闭，开启后用户列表和作品详情均不再展示失败记录，后台仍保留这些记录。在后台「历史作品」可永久删除单幅已结束作品，HTML 与回复一并移除，用户端下一轮刷新会撤下作品并关闭已打开的大图。绘制中和排队中的作品不能单独删除。

OAuth 监控只提供永久删除，点击后简单确认即可，无需输入名称，也不再选择归档。删除会清理该计划及全部作品、回复和糖果记录。账号管理删除账号时，同步永久清理关联的全部 OAuth 监控；升级也会清理此前已删除账号遗留的监控计划。后台已删除的活动任务不会重新写回记录。

开启后，登录用户的侧栏在渠道监控下方显示「鹈鹕监测」，地址为 `/pelican-monitor`。页面使用更宽的横向分组卡片，展示分组名称、当前分组倍率、检测间隔、下次检测倒计时、执行状态和最近作品；作品最新在左，可点击放大查看动画、检测时间、模型、思考强度与耗时。检测间隔从上一轮完成后计算，生成中和暂停时显示对应状态，不显示虚假的倒计时。这里的分组倍率不代表用户专属折扣后的最终计费价格。

用户只可查看，不提供立即检测、编辑或删除操作。只有后台选中的站内分组计划对用户可见，并且仍遵循用户现有分组权限；独占分组和订阅分组不会因此绕过授权。Key（包括掩码）、账号、上游来源、内部备注、模型原始回复和内部错误诊断均不通过用户接口返回。作品详情只展示安全的作品信息，不显示上游来源。

列表每 1.5 秒统一同步，新作品自动置顶；第一张标记「最新」，历史作品显示记录编号，绿点表示完成、红点表示失败、黄点表示等待或绘制中。页面内所有作品自动播放，无需悬停，横向滚动或打开大图不会重启已有动画。作品 HTML 使用共享加载队列并限制并发与缓存大小，短暂加载失败会有限重试；隐藏整个页面时暂停播放和刷新，返回后恢复。关闭展示、取消勾选、归档计划或失去分组权限后，用户接口会撤回相应列表和作品详情的访问。现有鹈鹕作品保留规则继续生效，不复制另一份历史数据。

### OAuth 监控

账号管理中，真实 OpenAI OAuth 账号可点击「测试」旁的「监控」，打开同一监控计划的弹窗。已有计划直接展示最近作品、实时账号状态与当前分组；尚无计划可固定当前账号创建，默认每 5 分钟定时检测、单次最多等待 10 分钟，保存后同步出现在上游中心的「OAuth 监控」。两个入口共用定时设置和历史记录，编辑、暂停或永久删除也作用于同一个计划；只打开弹窗不会发起检测。停用或周限额冷却账号仍可查看已有作品，新建及执行继续遵循账号可用性校验。弹窗仅查询当前账号，运行期间每 1 秒、空闲时每 5 秒刷新，隐藏页面或关闭弹窗后停止读取。

### 账号管理的 API Key 监控

OpenAI、Anthropic 和 Gemini API Key 账号也提供「监控」入口，弹窗上方展示上游分组的最近 60 次状态记录、七天可用率、最新延迟、缓存倍率，以及上游今日消费、今日用户消费和今日预估毛利；OpenAI 兼容账号下方展示该分组已有的鹈鹕和糖果测试。计划通过原有 `upstream_target_id` 关联，两个入口共用设置、作品和检测记录，不复制计划。

三项金额沿用上游中心同一分组的统计口径：上游今日消费来自最近余额同步快照，日期边界由上游决定；用户消费与预估毛利来自本站时区今日的分组账目，毛利扣除业务成本与已计价监控成本，不能直接用用户消费减去可能包含站外使用的上游消费。成本缺失时显示「—」并提示成本待补全，零值保留为 0.00，负毛利显示红色。金额随弹窗自动轮询与顶部刷新更新，仅聚合当前分组，不读取全站账目。

读取优先使用仍与当前地址及 Key 一致的账号绑定，再查找协议、地址与 Key 完全一致的上游分组，最后查找独立监控；同一优先级匹配多个分组时提示先明确绑定，不随意选择。没有匹配记录时，可点击「接入上游监控」，服务端使用账号已保存的凭据，幂等创建上游与分组；并发操作不会重复创建。新分组的状态检测默认关闭，需点击「配置状态监控」开启；鹈鹕计划继续使用现有创建表单及默认定时设置。只打开弹窗或接入分组不会发起模型检测。

已有独立监控保持原来的归属及检测设置。Anthropic、Gemini 账号可查看和配置状态检测，鹈鹕测试暂只支持 OpenAI 兼容接口。账号列表不逐行查询监控；仅打开的弹窗读取当前账号，状态检测开启时每 3 秒、关闭时每 5 秒刷新轻量状态，鹈鹕保持原有活动/空闲刷新节奏。顶部刷新同时更新状态与作品；隐藏页面或关闭弹窗即停止轮询。

「OAuth 监控」是独立 Tab，运行同一项鹈鹕动画任务，模型默认 `gpt-6-astra`，可选 `gpt-6.1-sol`、思考强度仍为 `high`、提示词完全一致。添加时只能选择站内已启用、状态正常且当前可调度的 OpenAI OAuth 账号，排除限流、过载、临时冷却、按策略过期停用、影子或合成账号。新增列表还会排除已经有同模型 OAuth 监控计划的账号，暂停中的计划同样排除；编辑时保留当前绑定账号。服务端在同一事务锁下阻止重复绑定，避免多个窗口同时添加；永久删除计划后可为该模型重新选择该账号。账号选择与其他智商监控下拉统一使用站内原生选择组件，不带搜索；选择后列表收起，当前账号以浅绿色背景标识。卡片使用账号名称并显示 OAuth 标识，无需输入 API Key 或自定义地址。账号改名后列表跟随当前名称，执行记录保留当次名称快照。 OAuth 标识下方显示当前账号的分组标签；多个分组分别展示，未绑定时显示「未分组」。分组绑定与名称跟随整页自动刷新及手动刷新更新，不使用历史作品中的分组快照。

执行明确指定所选账号，不经分组随机路由，也不会换到其他账号。服务端复用正常 OpenAI OAuth 转发通路的 Token 获取与刷新、账号代理配置以及账号和代理并发控制。账号必须支持所选模型且不能把它映射为其他模型；执行时还须处于可调度状态。普通临时限流或无可用并发等情况按原有逻辑记录失败；账号停用、删除、过期或周限额冷却时暂停新检测，不能把该账号不可用伪装成其他账号成功。

卡片左侧单独显示账号状态：绿色「正常」、琥珀色「周限额冷却」，不可用账号显示灰色。周限额依据当前账号身份匹配的 7 天额度与重置时间，或明确标记为 7 天额度的调度冷却判断；普通短时 429、5 小时额度和过载不会被标成周限额。可获取时显示预计恢复时间。

进入周限额冷却后，鹈鹕和糖果都暂停新请求，停止倒计时并禁用立即检测，保留定时开关、间隔和历史作品。后台每隔最多 30 秒复查一次账号的已保存状态，额度恢复且账号可调度后自动继续；复查不请求模型，也不反复创建失败记录。已经排队的任务在实际发出请求前再次校验；已经发出的请求不强制中断。账号状态随整页统一轮询和刷新更新，不增加每张卡片独立的网络请求。

OAuth 新建计划默认开启定时、每 5 分钟一次，可暂停定时；使用 Responses 接口，共享横版卡片、左新右旧的最近 20 条记录、作品预览和物理保留规则。

### 智商监控的费用口径

智商监控会发出真实模型生成请求，可能产生上游费用。本站分组来源按正常请求记账，使用的是创建计划的管理员专用监控 Key。上游 Key 与外部地址来源直接访问上游；其生成费用目前没有单独写入可用性监控的成本记录或厂家经营明细，可能仅反映在上游消费快照中。OAuth 监控直接使用指定账号，也没有单独写入厂家利润账，不将它视为一条普通本站分组消费。因此厂家预估毛利不能视为已扣除全部智商监控费用的现金利润，也不能把快照倍率当作这次生成的实扣金额。

上游和本站分组来源会尝试保存运行时倍率；失败或过期必须按该次快照状态解读。外部线路手填的倍率备注与自动获取字段分开保存。智商监控结果是否有效仍需结合真实接入权限、模型可用性、上游账单和作品内容判断。

## 接入与权限

后台管理与主动测试功能及接口仅管理员可见，不会出现在公开渠道状态页。用户端只读鹈鹕监测须由管理员开启，仅向登录用户展示选中的站内分组计划，并遵循现有分组权限。密钥加密存储，管理响应仅提供脱敏内容，用户展示接口不返回密钥或其掩码。外部探测、余额、倍率和智商监控请求仅允许公网 HTTPS，拒绝内网、回环、链路本地地址及重定向。智商监控的「本站分组」使用服务端专用的本机网关通路，不接受管理员填写任意内网地址。

新表由正常启动迁移创建，现有账号和渠道监控无需迁移到新中心。上游基础接口位于 `/api/v1/admin/upstream-center`，智商监控接口位于 `/api/v1/admin/intelligence-monitors`。基础接口定义见 [upstream-center-contract.md](upstream-center-contract.md)；调度、租约和数据保留细节见 [运行说明](../backend/dev-docs/upstream-center.md)。

本文是当前实现的使用说明，不代表任意实际付费上游已通过生成验收。真实模型调用、返回作品与费用应使用管理员自己的授权线路确认。

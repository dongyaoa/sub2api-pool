# 上游中心运行说明

上游中心 API 仅注册在管理员路由 `/api/v1/admin/upstream-center`。厂家的 Key 分组和独立监控共用目标配置与探测实现，但与现有渠道监控 V1/V2 开关、公共展示设置相互独立。

## 手动显示顺序

管理员可以通过 `PUT /api/v1/admin/upstream-center/order` 保存完整列表的顺序，请求为 `{ "scope": "suppliers" | "monitors" | "groups", "supplier_id": 123, "ids": [3, 1, 2] }`。仅 `groups` 必须携带正整数 `supplier_id`，其他范围不携带；`ids` 必填且必须是正整数、无重复，并涵盖该范围全部未归档记录。空范围允许 `[]`。非法输入返回 400 / `MANUAL_ORDER_INVALID`；记录新增、删除、移到其他范围等导致集合过期时返回 409 / `MANUAL_ORDER_CONFLICT`，客户端应刷新后重新排序。成功返回通常的 `data: null`，重新读取 overview 可取得已保存顺序。

迁移 `251_upstream_manual_order.sql` 添加三个可空 `sort_order` 列（厂家、监控目标、智商计划）。已有记录保持当前顺序；新建厂家自动排在上游列表和快捷切换 Tab 的第一位，其他厂家的相对顺序不变，之后仍可手动调整。厂家内的新分组、独立监控、智商计划及跨列表移入的记录继续排在已排序记录之后。厂家内的分组顺序、独立监控顺序与厂家顺序互相独立。API 不公开排序字段，以列表响应的数组顺序为准。

排序只改 `sort_order`，不改 `updated_at`、账号绑定、凭据、财务、检测时间、启停或运行快照，不产生任何上游请求。事务按列表串行排序，成员创建/归档/移组通过共享/排他 advisory lock 与完整集合验证协调，避免新增幻行或跨范围并发污染。正在检测或生成的卡片仍可排序；不要求暂停任务。

## 探测和记录

- 普通厂家 Key 分组、独立监控新建默认模型为 `gpt-5.6-sol`，默认每 30 秒一次，允许 30–3600 秒；每个模型独立请求、独立记录，最多 8 个模型。单模型超时允许 5–45 秒，默认 45 秒。迁移 `248_upstream_monitor_defaults.sql` 仅调整新建默认值与间隔约束，已有目标的模型、间隔和智商/OAuth 计划保持原配置。
- 新建启用目标在 5 秒轮询内进入检测；每个实例最多 5 个目标同时执行。PostgreSQL 条件租约排除跨实例及手动/自动检测重叠，租约 10 分钟，常规运行上限 7 分钟。
- 多模型按配置顺序检测。一次轮询完成后，下一次检测时间从完成时开始计算。暂停目标可以手动检测，完成后仍保持暂停。
- 活动探测期间，目标配置修改及归档返回 409，避免已发生的请求结果和费用因改配置丢失。管理员断开请求后，已完成的探测仍尝试写入记录；服务停止会取消探测并等待记录写入。
- 正常/波动均计为可用样本；失败和错误计为不可用。慢阈值默认 6000 毫秒。延迟是完整响应耗时，平均值与 P95 仅统计成功样本，不是首字延迟。
- 可用率支持 24 小时、7 天、30 天；另提供固定 7 天 `availability_7d` 给卡片展示，不随选择窗口变化。时间条独立展示该模型最近 60 次记录，旧到新排列，不混合模型。无样本为 `null`，不伪造 100% 可用。
- `latest_latency_ms` 为最新检测记录的延迟，包含失败记录；最新记录缺失延迟就返回 `null`，不回退至旧样本。卡片成功率复用渠道监控的连续红黄绿配色。60 条记录沿用 22px 高的原样式，各条宽度自适应铺满所在区域，悬停用现有 HelpTooltip 展示并复制已保存诊断；独立监控保留小卡和一行紧凑成功率/延迟指标。
- 页面「上次更新 N 秒前」每秒更新，是浏览器根据所选模型 `last_checked_at` 计算的时间差，不改变后台请求频率。

## 页面更新与大列表性能

上游管理和监控中心在当前页面可见时，读取完成后每 5 秒刷新一次；智商／OAuth 当前列表有排队或绘制任务时为 2 秒，否则为 5 秒。智商页面的上游来源与倍率快照每 30 秒更新一次。这里是轮询最新落库结果，不是 WebSocket 推送；不缩短实际模型检测或余额同步周期，也不会因刷新额外发起付费检测。

后台轮询不与尚未完成的读取重叠，也不取消慢请求；手动刷新会替换尚未完成的旧读取，并忽略过期响应。连续失败采用退避，最长 30 秒。页面隐藏或智商 Tab 不活动时暂停对应读取，回到页面、切换回来或网络恢复时立即重新读取。手动刷新智商列表同时刷新上游来源信息、重试未加载出的作品，已成功的预览 iframe 保持原位。相关管理 GET 响应使用 `Cache-Control: no-store`。

智商列表批量读取来源名称和作品摘要，每个计划最多返回最近 20 条已结束记录及 1 条活动记录；活动记录独立查找，不会被历史作品挤掉。列表不读取作品 HTML、原始模型输出或执行凭据。作品进入视口才加载详情，最多并发 4 个请求，重复读取合并；成功 HTML 的浏览器内存缓存按登录会话隔离，最多 64 条／8 MiB。离屏或隐藏时取消未完成加载，返回后重试。新任务入列时自动滚动至最左侧，及时显示绘制卡片。

Overview 的财务部分最多使用 4 次数据库查询，批量取得所有厂家的账目、目标账目、当前身份的余额及倍率快照；不再为每张卡片单独查询。业务账本、监控明细和小时费用汇总在查询区间内各聚合一次，保留历史厂家归属、独立监控隔离、未知费用／Token 及归档区间校验规则。智商列表批量读取计划、作品、糖果摘要和来源信息；存在站内分组时额外用一次查询读取分组与密钥显示信息，查询次数不随计划数量增加。单项详情 API 继续沿用原接口。

轮询复用未改变的卡片和历史对象，避免整页重绘；60 条监控记录的提示框仅在悬停时创建并监听全局事件，「几秒前」计时更新不重复渲染整条状态条。

## 凭据和归属

API Key 使用项目已有 AES-GCM 密钥加密，接口仅返回掩码。请求仅允许公网 HTTPS，提交时校验 DNS/IP，实际建连再次校验并拒绝重定向；监控记录仅保留脱敏、截断后的具体错误摘要，不保存完整原始错误响应。

厂家分组与独立监控均在创建后排入首次余额/倍率同步，包括手动填写 URL + Key 和从 API Key 账号导入的独立监控。后台每 10 秒检查到期目标，每次同步完成后约 1 分钟再次同步，与 30 秒可用性探测间隔独立。同步复用 `/v1/usage` 中的 Billing，缺失时读取 `/v1/sub2api/billing`；仅保存上游明确返回的真实倍率，支持零倍率，缺失或不支持保持未知，不补成 1×。更换地址、Key、厂家或钱包身份会重新排入首次同步。Overview 只读本地快照，不触发外部网络请求；同步结果和错误在后续页面刷新中显示。

厂家分组可关联多个现有 API Key 账号，所有账号必须与分组使用相同 endpoint 和 Key。每个账号只能有一个活动归属。保存时在事务中再次锁定并校验账号凭据，避免并发修改造成错误归因；重复 endpoint+Key 的活动厂家分组会被拒绝。

独立监控可通过仅输入的 `source_account_id` 导入现有 API Key 账号。保存时由后端读取账号凭据，加密复制到新监控，不返回明文、不持久化来源关系、也不创建业务账号绑定；`account_ids` 必须为空。来源必须为启用且可调度开关打开、未自动过期的实际 API Key 账号，不能使用影子/合成测试账号或空 Key。显式传入的地址、平台必须与来源匹配，缺省时从来源补齐；`source_account_id` 与非空 `api_key` 同传会被拒绝。前端手动改地址、平台、Key 时清除待导入来源；编辑再次选择来源才重新复制，普通编辑保留已保存的 Key，不因原账号改动暗中换 Key。模型发现可以使用 `account_id` 读取新来源模型，来源优先于编辑中的旧 `target_id`，并应用相同来源校验。

现有目标更换地址或平台时，后端禁止自动沿用旧 Key；必须显式填写 Key、导入新来源，或使用与新地址、平台和 Key 精确匹配的厂家绑定账号凭据。取消待导入来源而保留新地址的表单也遵守这一约束，避免把旧 Key 发送至另一个上游。只改名称、模型、周期、暂停状态，或地址只增加末尾斜线时可以保留原 Key。源账号跨平台导入且未显式提供 `api_mode` 时重置为通用默认，避免沿用不兼容的 Responses 模式。

绑定使用有效时间区间；业务消费按 `usage_logs.created_at`（完成记账时刻）匹配归属。改 Key、改厂家、解绑或归档均关闭旧区间，保留旧账。厂家 ID、厂家名称和目标名称在绑定及监控记录中保留快照。正在进行的请求在绑定变更后完成时，按完成时的有效归属记账，因此属于账面估算。

## 成本与保留

### New API 上游

普通地址 + API Key 会先识别 Sub2API；接口不支持或返回不兼容认证响应时，再识别 New API 的 `GET /api/usage/token/`。仅接受明确的 `token_usage` 成功响应，读取当前 Key 的剩余额度、累计消耗和无限额度标记。Key 额度与账户钱包分开显示，不把无限额度当作余额为零。金额使用 `/api/status` 返回的 `quota_per_unit` 换算为系统 USD 额度；不使用充值价格或显示汇率。单位缺失、无效或换算溢出时保留原始 `QUOTA`，不猜测固定换算比例。

读取账户钱包和真实分组倍率需要在分组／独立监控的「New API · 余额与倍率授权」中填写该上游的用户 ID 和个人访问令牌（控制台访问令牌，不是模型 API Key）。新版 New API 接受 Bearer PAT，旧版同时要求 `New-Api-User`；这里始终发送两者。只执行读取接口：`/api/user/self`、`/api/token/search`、`/api/token/:id`、`/api/user/self/groups`。精确查到当前 Key 且所有用户 ID 匹配后才采用账户钱包；Key 分组为空时继承用户分组，倍率读取带用户覆盖的 `/self/groups`，不把公开报价当作个人实际倍率。`auto` 分组显示动态倍率并清除旧的固定倍率，缺失倍率保持未知，零倍率有效。智商监控选择这些上游分组时复用相同的实时快照。

New API 普通 Key 额度端点的官方默认限流为同 IP 20 次／20 分钟。成功读取后，Key-only 额度约每 20 分钟同步，并按站点限制请求速率；此间隔不影响可用性检测。启用控制台授权后跳过该端点，按原有约 1 分钟周期同步；首次精确查询后缓存经过归属验证的 Token ID，后续读取 ID 接口，减少搜索限流。缓存按站点、Key、用户 ID 和控制台凭据身份隔离，凭据变更不会复用旧结果。余额同步总请求预算 45 秒，小于 60 秒租约。

New API 不提供可靠的 Key 级完整今日费用接口，最近日志的条数有上限，不能冒充全天统计。因此上游报告的今日消耗保持未知，本站业务金额、请求数与 Token 统计继续使用现有账本；累计消耗仅取该 Key 的统计。共享钱包按站点、用户 ID、钱包标签和币种去重，不将不同用户的钱包合并，也不将多个 Key 的同一个钱包相加。

迁移 `253_upstream_newapi_credentials.sql` 仅追加可选加密凭据、无限额度字段及倍率来源类型。响应只返回用户 ID 与是否已授权，不返回控制台令牌或密文。修改地址、平台或用户 ID 必须重新填写令牌或明确关闭授权；修改凭据立即安排同步，写入时校验凭据身份。精确搜索 API 的查询包含 Key，因此本地错误和快照不得保存原始请求 URL 或完整上游响应。所有请求仍使用同一公网 HTTPS／DNS 复核和禁重定向客户端。

接口契约核对版本：官方 QuantumNous/new-api `v0.10.8`、`v1.0.0-rc.40`（`0aec08fee811ec6136828fda790551b49e410301`）。第三方修改版关闭这些读取接口时，页面展示具体缺失能力，不推算余额或倍率。

探测响应提供完整 token 使用量时，财务服务按账号采购配置或默认模型定价估算监控费用。未返回完整 token 计数或无定价时费用为未知，利润不会把这些请求当作免费。用户消费为账面额度消费，不代表现金收入。

同一厂家内，`wallet_ref` 表示运营者配置的共享钱包身份。共享 wallet 按同 ref、同 currency 选取最新的真实余额观测，金额、来源 Key、同步时间与状态一起保留，从不把多个 Key 的余额相加。已有同名钱包时，另一个 Key 的 401、待同步或不支持响应不会额外产生一个钱包；各 Key 的 `target.balance` 仍保留其原始失败状态。尚无任何可信钱包余额时保留未知占位，不伪造零。明确的 `key_quota`、`subscription` 按 Key 隔离，不同币种也不合并。多个实际独立的钱包应配置不同 `wallet_ref`。

监控采购估价比较所有绑定账号及其分组的可识别价格。自定义成本与默认成本冲突时，或渠道要求使用实际客户账单定价而直接探测没有该账单时，费用保持未知，不任取一项生成精确利润。

业务账目 `upstream_finance_ledger.total_tokens` 保存输入、输出、缓存写入与缓存读取之和。迁移 `247_upstream_finance_usage_totals.sql` 从仍存在且匹配的使用日志回填；原日志已清理而无法恢复的旧账保留 `NULL`。汇总有任何未知记录时 `total_tokens=NULL` 并返回 `unknown_token_requests`；没有业务请求时为零。UI 以 M 显示，达到十亿时换为 B，同时保留 `request_count` 业务请求数。Key 行右侧财务金额使用纯数字，币种在 title/详情中保留；这只是格式变化，不改变 API 金额单位或会计口径。

`account_billed` 返回业务账目历史账号计费之和，当前与 `business_cost` 相同：`COALESCE(account_stats_cost,total_cost) * COALESCE(account_rate_multiplier,1)`。零倍率有效，来源为记账快照，不依赖账号当前配置。它不是用户 `actual_cost`，也不包括监控费用。

### 存储清理与永久删除

存储管理默认启用自动保留策略：可用性监控明细保留 30 天，余额／倍率快照完整保留 7 天。管理员可将监控明细调整为 30–365 天、快照调整为 1–90 天；关闭自动清理后仍可手动执行一批清理。后台按小时检查，存在积压时每分钟续跑有界批次；每批每张表最多删除 5000 条、事务最长 30 秒，并使用数据库事务锁避免多实例同时清理。不会在启动时整档永久删除，也不会为了释放空间执行 `VACUUM FULL`。

监控明细到期前，先按 **UTC 整小时、检测时的目标与厂家归属**汇总监控成本、未知费用数量和费用来源数量，再在同一事务删除对应原始明细；重复运行不会重复计费。保留边界向下取整到 UTC 小时，完整保留边界小时，因此 7 天／30 天可用率与明细统计仍有原始数据可查。卡片的 60 条状态记录表示保留窗口内最近 60 次，而非另行永久保留 60 条。归档目标的旧明细也适用相同策略。

费用汇总表 `upstream_monitor_cost_rollups` 与业务账本 `upstream_finance_ledger` 不随保留期删除，也不外键依附当前厂家或目标。财务汇总同时读取未清理明细与历史小时汇总，监控成本、未计价数量、来源和利润口径保持一致；业务请求账本仍可按原精度查询。每个小时汇总另存实际首个／最后一个样本的精确时间，查询区间完整涵盖这些样本或与之完全不相交时可正常计算，因此永久删除当前小时的监控后，「截至现在」仍可正常查询。仅当半开区间 `[from,to)` 真正切穿某组已汇总样本的首末时间范围时，接口返回 `UPSTREAM_FINANCE_ARCHIVED_RANGE`，要求扩大到完整小时或日期，不把整个汇总费用冒充局部时段费用。UTC 整小时边界始终可查询；时区不是 UTC 整小时偏移时，可切换至 UTC 整小时边界查询这部分历史。

余额／倍率快照在保留期内完整保留；过期后，只额外保留每个目标**当前凭据身份**最近一次及最近一次成功观测。当前身份包含地址、协议、厂家、钱包标签、模型 Key 以及可选 New API 用户 ID／控制台凭据；更换 Key 后不会把旧 Key 的历史余额作为新 Key 兜底。旧身份的过期快照可清理；归档不会让这些快照永久无限累积。

归档仍表示停止调度并保留配置与历史。在存储管理的归档清单中可找到已归档厂家、分组／独立监控及智商／OAuth 计划；执行永久删除必须选择具体对象并输入其当前名称确认。永久删除厂家或目标前，监控明细仍先汇总费用，随后删除选中对象的配置、绑定和余额／倍率快照，历史业务账本与小时费用汇总继续保留。关联智商计划暂停并解除上游来源，已有作品保持各计划的保留规则；永久删除具体智商／OAuth 计划时才删除该计划及作品，并停用、失效其专用本地 API Key 缓存。正在检测、同步或有排队／执行中作品的对象返回繁忙，不强行中断。

清理删除的是数据库行。PostgreSQL 常规回收后可复用相应页空间，但数据库文件和操作系统看到的磁盘占用不保证立即缩小；该功能不执行会长时间独占锁表的 `VACUUM FULL`。容量判断应同时观察表大小、可复用空间与后续增长，而不是只看清理按钮后的文件尺寸。智商／OAuth 作品仍按每计划最近 20 条已结束记录保留，自动存储清理不会额外删除整计划或业务账本。

## 智商作品保留与 OAuth 执行

### 上游分组内查看智商监控

上游管理的 OpenAI 兼容 Key 分组提供「智商监控」入口，按需打开该分组的横版计划与作品弹窗，复用原智商监控的计划、作品和调度；不复制 Key，不生成另一套历史。未关联计划时可在弹窗创建，自动使用分组名并锁定来源，仍允许修改计划名。新建默认最长等待 10 分钟、检测间隔 5 分钟且定时开启；保存后参与调度，也可在保存前关闭定时以仅手动检测。打开或关闭弹窗本身不会创建计划或发起生成。编辑已有计划保留原启停状态与间隔。已有计划可查看作品详情、编辑、暂停及使用原删除流程，原智商监控 Tab 继续可用。

弹窗仅请求 `GET /api/v1/admin/intelligence-monitors/plans?upstream_target_id=<正整数>`，数据库先按 `source_type='upstream'` 和目标 ID 过滤，再批量读取摘要；空列表返回 `items: []`，重复、空或非法目标参数返回 400。迁移 `256_intelligence_upstream_plan_lookup.sql` 添加按分组查询的非唯一索引。创建或迁入已有未归档计划的分组时，事务成员锁串行检查并返回 409／`INTELLIGENCE_UPSTREAM_PLAN_EXISTS`；暂停计划同样视为已关联。旧重复计划全部保留、可在原分组编辑或暂停，不通过迁移删减作品。

弹窗采用活动任务或即将到期时 1 秒、空闲 5 秒的无重叠轮询，关闭后取消读取并卸载作品预览，未打开的分组入口不发出智商查询。预览继续使用视口按需加载、最多 4 并发和成功缓存；刷新不会重新创建已成功的 iframe。打开作品详情时暂停下层缩略图播放，详情正常自动播放并跟随列表完成信号刷新；多层弹窗独立处理 Escape、焦点和页面滚动锁。目标被移除、变为不兼容协议或切走上游 Tab 时关闭弹窗，旧请求结果不会进入另一个分组。

智商监控、站内监控和 OAuth 监控共用 `/api/v1/admin/intelligence-monitors`，在 UI 中分为三个 Tab。任务固定使用 `gpt-6-astra`、`high`，提示词为 `创建一个 HTML，内容是用 SVG 绘制一个鹈鹕骑自行车的 2D 动画。你不需要任何测试。`。界面新建计划默认开启定时检测，间隔 5 分钟，保存后参与调度。全部来源及上游分组弹窗的鹈鹕间隔统一提供 5/10/15 分钟和自定义（30–86400 秒），其他已保存的合法间隔按自定义原值回显；已有关闭定时的计划编辑时仍保持关闭，关闭浏览器不影响已排队任务。

界面新建的全部智商来源默认最多等待 10 分钟，提供 5/10/15 分钟选项，API 接受整数 180–900 秒以兼容旧设置。迁移 `250_intelligence_monitor_generation_timeout.sql` 将已有 180–300 秒计划统一提升到 900 秒，仅改 `timeout_seconds`，保留启停、下次执行时间、`updated_at` 等其他配置；已排队、执行中及历史记录的超时快照不改，也不自动重放。任务租约按本次超时加 180 秒生成，15 分钟任务的租约为 18 分钟，防止旧 8 分钟租约提前结束正在生成的作品。

每个计划最近 20 条已结束鹈鹕执行（`succeeded`/`failed`）按 `created_at DESC,id DESC` 保留，横版卡片左新右旧。`pruneIntelligencePlanRuns` 在完成或租约过期事务内持有计划锁清理旧行；启动调用 `PruneRuns` 清理已有超量数据，归档计划也处理。超出部分的记录及 HTML/原始回复物理删除；`pending`/`running` 排除在保留删除之外，因此存在活跃任务时总数可暂时大于 20。此规则只适用于智商作品，不能套用于财务依赖的可用性监控记录。

### 可选糖果测试

迁移 `257_intelligence_candy_monitor.sql` 为计划增加默认关闭的 `candy_enabled`，为执行记录增加 `test_kind`、`correct` 和 `answer`；原记录默认归类为 `pelican`。新建或编辑计划时可开启糖果测试，智商监控、OAuth 监控和上游分组弹窗复用同一开关与记录。未开启的卡片不渲染糖果区域，保留原布局；开启后在作品区上方显示最近 60 次糖果结果及当前活动记录。请求成功且答案正确显示绿色；答案错误或请求失败显示红色；未执行、排队和执行中保持各自等待状态。悬停可查看答案、模型、思考强度、时间、耗时与错误，点击按需读取完整回复。

糖果题目由服务端固定，只发送用户提供的题干和数量表，不发送参考答案。模型、思考强度与所选来源沿用计划设置（当前固定 `gpt-6-astra`、`high`），不提供外部工具。评分版本 3 与参考项目保持一致：回复出现独立数字 `21` 即通过，支持 LaTeX、Markdown 和全角数字；`121`、`210`、`021` 不通过。规则不进行语义结论判断，推导、引文、备选答案中的独立 `21` 以及 `21.5` 也会通过，原回复保留供核对。请求正常完成时 `status=succeeded` 与 `correct` 分别表示传输完成和答案是否正确，HTTP 错误／空回复仍为 `failed`，不与答错混淆。

迁移 `260_intelligence_candy_grading_version.sql` 添加评分版本和修复索引；新完成的糖果请求写入当前评分版本。独立后台循环对旧版本、无调用错误的已完成糖果记录重新评分，每批最多 32 条，事务内使用 `SKIP LOCKED`，每条原文最多读取 64 KiB 供评分，完整原文保持不变。修复只更新 `answer`、`correct` 和评分版本，不修改请求状态、原始回复、执行时间、来源或计费，不请求上游；已评分记录不会重复处理，取消时回滚整批，失败后重试。

每轮糖果测试只发送一次固定糖果题请求，使用 `high` 思考强度，不附加采样或模型对比请求。题目响应完成后直接按当前评分规则记录结果；HTTP 错误和超时保留原失败状态。糖果与鹈鹕继续使用独立的并发名额和调度循环。

`POST /api/v1/admin/intelligence-monitors/plans/:id/candy/run` 仅对已开启糖果功能的计划手动入队一次糖果测试，原 `POST /plans/:id/run` 仍只生成鹈鹕。迁移 `258_intelligence_candy_schedule.sql` 增加独立糖果间隔、上次和下次检测时间，默认 180 秒，仅允许 180/300/600/900 秒（3/5/10/15 分钟）。两种测试分别到期入队，分别产生模型消耗；完成或超时仅从完成时刻重新计算自身的下次时间。修改一个间隔不重置另一个倒计时，改名称、备注不重置计时。首次开启参与下一次调度；暂停清空两种后续计划，但不强制中断已排队任务。

同一计划的鹈鹕和糖果可同时执行，每种最多保留一份活动任务；长时间绘制不再让同计划的糖果等待，反之亦然。默认支持 8 个鹈鹕请求并行，糖果独立使用 4 个名额，不占用绘制名额。数据库在短事务内按类型检查运行数量并领取任务，所有连接同一数据库的实例共享上限，仍按各类型入队顺序执行。`(plan_id,test_kind)` 活动唯一索引继续防止同一测试重复提交，领取锁继续防止跨实例超额或重复执行。

上游中心右上角「并发设置」可在线调整鹈鹕（1–256）和糖果（1–128）上限，并查看当前运行与排队数量。管理员 `GET/PUT /api/v1/admin/intelligence-monitors/concurrency` 读取／完整更新两个整数值；保存到已有 `settings` 表的 `intelligence_monitor_concurrency` JSON 配置，不需要新增表或迁移。保存与任务领取使用同一数据库 advisory lock，领取时读取当前配置，所有实例立即遵守新上限；本实例保存后主动唤醒，其他实例由 1 秒领取轮询生效。降低上限不取消正在进行的模型请求，等占用降到新上限以下再领取新任务。重启后仍保留后台设置。

尚未在后台保存时，使用部署配置 `intelligence_monitor.max_concurrency`（默认 8）与 `intelligence_monitor.candy_max_concurrency`（默认 4）；对应环境变量为 `INTELLIGENCE_MONITOR_MAX_CONCURRENCY`、`INTELLIGENCE_MONITOR_CANDY_MAX_CONCURRENCY`。修改部署配置需要重启，多实例须使用一致配置；后台保存后优先使用数据库值。两项均不接受 0 或无限模式。上限限制并发请求和输出缓冲资源，而不是限制可创建计划数量。

到期扫描每 3 秒执行，每批最多 256 个鹈鹕计划、128 个糖果计划；保存计划会唤醒扫描。两种任务各有独立领取循环、唤醒信号和超时预算，入队、完成或保存并发设置后立即唤醒，另每秒检查其他实例提交的任务或释放的名额。一种任务的慢领取不会阻塞另一种任务领取或补位，来源查询、到期扫描和启动清理也不会阻塞已有队列。配置名额占满时仍会排队；账号及上游自身的并发限制继续生效。检测间隔是完成后的等待时间，并非严格的墙钟周期。界面分别显示两种测试的倒计时与排队／执行状态，不新增卡片网络轮询。迁移只初始化一次独立计时，重复执行不会重置已有倒计时。

`GET /runs?plan_id=:id` 默认仅返回鹈鹕记录，附加 `test_kind=candy` 可查询糖果历史；`GET /runs/:id` 读取对应详情。糖果独立保留最近 60 条终态，不挤占 20 条作品额度。列表按计划批量读取轻量糖果摘要，不加载原始回复、HTML 或执行凭据；未开启的计划不读取糖果摘要。两种任务共用父面板的活动或即将到期 1 秒／空闲 5 秒轮询与手动刷新，不新增每卡片请求或定时器；并发设置打开时每 2 秒刷新计数，保留未保存的输入。归档、永久删除及存储清理的繁忙检查覆盖两种活动任务，永久删除计划同时删除糖果历史。

### 用户只读鹈鹕监测

管理员通过 `GET/PUT /api/v1/admin/intelligence-monitors/public-display` 管理用户展示设置，使用已有 `settings` 表中的 `intelligence_monitor_public_display` JSON，不增加迁移。配置包含 `enabled`、`title`、`description`、`notice` 和 `plan_ids`，默认禁用且列表为空；文案长度上限分别为 60、240、1000 字符，最多选择 200 个不重复的正整数计划 ID。保存时复核计划为有效的 `local_group` 来源，不修改调度或生成记录。

登录用户使用 `GET /api/v1/pelican-monitor/config`、`GET /api/v1/pelican-monitor` 和 `GET /api/v1/pelican-monitor/runs/:id`。接口位于 JWT 用户路由组中，并遵循现有用户分组可用权限；展示开关及选中计划由服务端强制检查。列表只查询轻量鹈鹕摘要，批量读取每个计划最近 20 条终态及活动任务，不读取 HTML、原始回复、来源快照或糖果记录。详情仅在请求时读取作品 HTML。

用户响应使用独立白名单 DTO，不序列化管理员计划或执行对象。只提供分组名、分组当前基础倍率、间隔、倒计时目标、公开执行状态与时间、固定测试模型/思考强度，以及详情 HTML；错误转换为通用提示。历史记录必须与计划当前的 `local_group` 分组身份一致，换绑分组前的作品不随新分组暴露。未选中、已归档、关闭展示、用户无分组权限、其他来源或糖果记录不能通过直接 ID 读取。

前端 `/pelican-monitor` 使用独立 API 与作品缓存，不调用管理员详情接口。整页共用 1.5 秒轮询，按记录 ID 合并新状态并保留已有 iframe；卡片中的所有作品自动播放，不使用悬停或视口相交条件控制播放，打开大图也不暂停列表。页面隐藏时统一暂停播放和读取；详情仍共用最多 4 个并发及 64 条／8 MiB 缓存，临时加载失败按 1、2、4 秒间隔最多重试 3 次，切换作品、隐藏或卸载时取消等待。作品继续使用隔离 iframe 和现有预览清理运行时；不向作品提供同源权限、外部请求或导航权限。已取消读取的迟到响应会被丢弃，登录身份变化或展示关闭时清除用户作品缓存。后台「用户展示」入口仅出现在站内监控 Tab。

### 站内分组与实际执行来源

站内监控使用单列横向卡片：左侧集中显示分组名、当前分组倍率、密钥名称和掩码、定时状态及操作，右侧为同尺寸的小作品横向列表，可选糖果记录位于作品上方。卡片不显示最近一次生效倍率，执行倍率仍保留在历史详情中。作品按最新在左排列，保留 20 条终态与独立活动记录；新活动任务才滚回最左，普通刷新与任务完成保留滚动位置和作品 DOM。已有 `local_group` 计划直接在新 Tab 展示，不复制计划和历史；手动排序只移动对应子集，同时保留其他智商计划的相对顺序。

可从当前管理员已有的启用、未过期且额度可用的密钥中选择，分组固定为该密钥所属分组；也可继续选择自动创建仅限回环地址使用的专用密钥。后端复核用户归属、分组、额度、有效期和 IP 规则，不改变已有密钥的绑定、额度或限制；密钥 IP 规则必须允许 `127.0.0.1`。计划接口只接收／返回密钥 ID、名称和掩码，不返回明文。另一个监控计划拥有的专用密钥不得借用。

迁移 `259_intelligence_local_key_ownership.sql` 区分引用的已有密钥与自动创建的专用密钥。引用密钥在替换、归档或永久删除监控计划时保持有效；仅自动创建的专用密钥沿用停用和缓存失效逻辑。执行仍经过正常站内 API Key 鉴权、分组路由和计费，不绕过账户、IP、余额或额度检查。

站内鹈鹕大图和糖果详情显示本次实际执行账号／上游。来源由可信的一次性回环请求上下文传递，在真正转发之前记录账号；发生重试或切换时保留最后一次实际转发账号及尝试次数。成功响应显示完成来源，失败仅显示最后尝试账号；未到转发阶段或旧记录没有来源数据时明确显示未知，不从当前分组或最新使用日志推测。

作品保存时，按最后一次实际转发的时间匹配账号当时的上游绑定有效区间，确定当时的厂家／分组 ID，并固化这些 ID 在保存时对应的名称；实体已被永久删除时退回绑定名称快照。之后改绑、重命名或解绑不会改写旧作品来源。无绑定、重叠绑定或查询失败分别标记，不妨碍作品保存。来源地址只保存配置中的站点 origin，不保留路径、查询参数或凭据。该记录用于判断请求来源，财务归属仍使用原账本口径。

### OAuth 执行

OAuth 来源为 `openai_oauth`，迁移 `246_intelligence_monitor_oauth.sql` 加入 `account_id`。管理员选择站内已有 OpenAI OAuth 账号，名称跟随账号当前名称，运行快照保存当次名称与账号。服务端校验账号类型、固定模型能力、未重映射以及执行时可调度状态，拒绝影子/合成测试账号。

执行直接指定该账号传入正常 OpenAI OAuth gateway `Forward`，复用 Token 获取/刷新和代理配置，先获取账号与所选代理的并发槽；不可用代理排除后再选择，槽不可用则失败。没有按分组随机路由或自动改用其他账号的行为。超时/取消会结束后台请求；不把一次中断任务自动重发以避免重复费用。

OAuth 计划通过现有 membership 事务锁约束同一 `account_id` 只能新绑定一份未归档计划（包含暂停计划），冲突返回 `INTELLIGENCE_OAUTH_PLAN_EXISTS`。旧版本已存在的重复计划可原位编辑或暂停，不自动删除；归档释放对应绑定。

管理员计划列表通过单次批量账号投影附加 `oauth_account_status`，仅返回 `status`、`monitoring_paused`、可用的 `reset_at` 与 `weekly_used_percent`，不加载访问／刷新 Token。状态判断复用网关的规范化 7 天额度窗口及身份匹配规则，兼容 primary/secondary 窗口互换和显式 7 天阈值冷却，忽略普通 429 和 5 小时额度作为周限额证据。入队及实际转发前重新校验，周限额冷却返回 `INTELLIGENCE_OAUTH_COOLING_DOWN`，两种测试均停止新入队；缺失、停用、过期或来源无效的账号返回 `INTELLIGENCE_OAUTH_UNAVAILABLE` 并同样推迟复查，避免重复失败记录。

冷却时仅推迟现有下次执行时间至最多 30 秒后复查（更早重置则按重置时间），保留启停、配置间隔及 `updated_at`。到期扫描不写失败作品、不触发模型调用；读取到恢复额度或重置时间已到后按原定时设置恢复。手动暂停仍可执行，已发出的生成请求不主动取消。前端冷却时停止倒计时并采用空闲轮询，历史作品 DOM 保持不变。

OAuth 作品与其他智商来源一样保存时间、HTTP 状态、错误、固定参数及可获取的来源快照。原始作品与隔离预览分开；预览固定 960×600 等比缩放，使用允许动画脚本、但不授予同源权限的 sandbox iframe。直接 OAuth 执行未单独写入厂家经营费用，不能视为普通本站分组扣费或已计入厂家毛利。真实账号生成、作品和费用仍需使用授权线路核实，本文不声明付费生成验收。
